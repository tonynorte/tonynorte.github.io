Event-driven notifications for a digital-signature platform

Babel, for PROCOMER · 2026

  • Azure Logic Apps
  • Node.js
  • SQL Server
  • Office 365
  • PowerShell
The problem
Signers and viewers needed reliable email updates at every step of the signing process, and the platform had no dedicated notification layer.
What I did
I designed and built the service end to end. I defined the JSON event contract and the integration patterns: post-commit publishing, retries with backoff and correlation IDs. The workflow answers with an async 202, routes each event, and sends emails in parallel. Callbacks from the external signing service are validated with tokens.
The result
A fault-tolerant flow with automated admin alerts, where every event can be traced from the back end to the inbox. I validated each event and failure scenario with test scripts, and I still own the service in production.
